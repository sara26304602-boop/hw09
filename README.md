## 一、程式用途與 Colab 開啟執行說明

### 1. 程式用途
本程式用於自動清理與整理「桌遊體驗」與「電影欣賞」兩場活動的原始報名名單。它能自動將英文姓名轉為小寫並移除多餘的半形空白，接著利用 Python 的集合（Set）進行去重。程式會自動計算：
* 兩場活動各自的去重人數與應收費用
* 跨場重複報名的「共同參加者」
* 各場專屬的「單場參加者」
* 至少參加一場的「總不重複人數」以及代表總門票數的「總報名人次」

最後將數據格式化輸出，並提供前兩位排序名單作為通知預覽，方便主辦人一目了然地掌握活動狀況與財務摘要。

## 三、個人回答

### 問題一： 測試一中，整理後的桌遊串列有 4 筆資料，為什麼桌遊費用應以 3 人計算？直接把字串拆成 list，和再轉成 set，各自保留了什麼、失去了什麼？

* **桌遊費用以 3 人計算的原因**：
  在原始桌遊名單中，`" Amy"` 經過去除空白與轉小寫整理後為 `"amy"`，這與另一個本來就是小寫的 `"amy"` 是同一個人。根據主辦人設定的規則，同一個人在同一場活動中重複出現時只計算一次費用。因此去重後，桌遊的有效參加者僅有 `amy`、`ben`、`cora` 共 3 人，故費用以 3 人計算（3 × 120 = 360 元）。
* **字串拆成 List 與轉成 Set 的保留與失去**：
  * **字串拆成 List（串列）**：
    * **保留了**：元素的「原始順序」以及「重複出現的資料項目」（我們能知道哪些人重複報名了幾次）。
    * **失去了**：元素唯一性的保證，無法直接進行非重複性計算。
  * **List 轉成 Set（集合）**：
    * **保留了**：元素的「唯一不重複性」，且能直接進行高效的集合運算（如聯集 `|`、交集 `&`、差集 `-`）。
    * **失去了**：資料的「原始順序（無索引值）」以及「重複項目與其頻率資訊」。

### 問題二： 測試三中，兩場活動只有 3 位不同的人，為什麼是 6 人次、總應收仍是 600 元？請用集合關係與算式說明。

* **為什麼是 6 人次、總應收仍是 600 元**：
  * **總不重複人數（聯集）** 是指至少參加一場活動的人頭數。在測試三中，桌遊集合 $A = \{\text{'amy'}, \text{'ben'}, \text{'cora'}\}$ 與電影集合 $B = \{\text{'amy'}, \text{'ben'}, \text{'cora'}\}$ 完全相同，因此他們的聯集 $|A \cup B| = 3$ 人。
  * **報名人次** 是兩場活動各自去重後人數的加總（即 $|A| + |B|$）。因為規則允許同一人跨場報名且兩場活動獨立計費，因此這 3 個人兩場都有報名，計為 $3 + 3 = 6$ 人次。
* **集合關係與費用算式**：
  總應收金額並非「總不重複人數」乘以單一費用，而是各場活動去重人數乘以該場單價後的總和：
  $$\text{總應收} = (|A| \times \text{桌遊單價}) + (|B| \times \text{電影單價})$$
  $$\text{總應收} = (3 \times 120) + (3 \times 80) = 360 + 240 = 600 \text{ 元}$$
  雖然總共只有 3 位不同的人，但因為這 3 位皆跨場參加，兩場的票價各自獨立收費，故總應收金額仍是 600 元。
